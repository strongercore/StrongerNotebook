# StrongerNotebook | 强者记事本
基于 C++17 + FLTK 开发的本地离线笔记系统，主打复盘、事件长期追踪。
> 核心信条：旧迹既定，仅供观省；只可追加，不可改史。

## 📌 设计理念
普通笔记软件大多按**写入时间**流水记录；
强者记事本以【事件原始发生日期】作为锚点。
该事件所有复盘、感想、补充记录，全部归集到事件当天的文件夹，方便从头到尾追溯整件事完整的思考脉络。
**已经保存的历史笔记正文永久只读，仅允许追加新记录，禁止修改过往内容。**

## 🛠️ 技术栈
- 编程语言：C++17
- GUI框架：FLTK（第三方开源GUI库，需要自行准备）
- JSON库：nlohmann/json（第三方开源单头JSON库，需要自行下载引入）
- 数据存储：纯文本 TXT 保存正文 + JSON 索引加速检索
- 运行模式：纯本地离线，无联网请求、无后台自动上传

## ✅ 功能清单
- 双分区布局：阅览区（只读历史笔记） + 编辑区（撰写新内容、追加复盘）
- 左侧树状目录：按年→月→日期层级浏览笔记
- 右侧标签面板：标签双向索引，快速筛选检索笔记
- 独立笔记标题输入框，标题和正文分开管理
- 自适应窗口缩放，控件对齐精细调校，可设置最小窗口防止布局错乱
- 索引重建功能：手动在外部增删txt文件后，一键扫描磁盘同步索引
- 自定义界面装饰符号，支持圆点、分隔符排版美化
- 静态编译可打包为单文件exe，无需额外运行库，低配老电脑也能流畅运行

## 📂 存储结构
程序 exe 同级自动生成 `LOGS/` 作为数据根目录（程序运行时自动创建，仓库不包含此文件夹）

LOGS/
- index.json：索引缓存，仅用于加速加载；txt 文件才是唯一真实数据源
- 年份文件夹（例：2026）
  - 月份文件夹（例：11）
    - YYYYMMDD 日期文件夹（例：20261110）
      - 主日志：YYYYMMDD.txt（单日唯一主日志）
      - 复盘 / 追加补充文件
      - 其他附属文本

### 文件命名规则（自动去重，防止覆盖）
- 主日志：`YYYYMMDD.txt`，一个日期文件夹只能存在一份主日志
- 补充复盘文件：以**补充操作当天日期**作为文件名，自动追加序号 `(1)(2)(3)` 区分
  > 跨天补充：第一次直接 YYYYMMDD.txt，后续递增序号
  > 当天补充：直接从 YYYYMMDD(1).txt 开始，避免覆盖当日主日志

### TXT 文件内嵌元数据（双保险）
每一份txt头部固定两行标记，程序读取时自动识别这两行，记事本直接打开也可见：

#tags: 标签1, 标签2
#title: 自定义笔记标题

> 说明：元数据放在txt文件最开头，程序读取识别；普通文本编辑器打开也能正常阅读笔记正文。

就算 `index.json` 损坏、丢失，笔记自带标题和标签信息，重建索引优先读取文件头部元数据。

### index.json 索引结构
顶层两个核心键：`date_map`、`tag_map`，双向索引
1. `date_map`：文件映射信息
    key：日期文件夹+文件名，全局唯一
    value: `{"title": "标题", "tags": ["标签1","标签2"]}`
2. `tag_map`：标签反向检索
    key：标签文本
    value：数组，存放绑定该标签的全部文件唯一key

## 🎯 按钮交互说明
- **新建今日日志**：创建当日主日志；当日已有主日志则禁止重复新建
- **追加复盘**：选中目标笔记/日期文件夹后，把编辑区内容追加存入对应日期目录，自动命名去重
- **检验&重建索引**：全盘扫描LOGS下所有txt，读取头部元数据，覆盖重建index.json
- **恢复目录树**：仅刷新界面目录树控件，不重新扫描磁盘文件
- **增修标签**：输入框有文字、无选中标签=新增标签；选中标签=修改已有标签
- **删除标签**：选中标签后执行删除

## ⚠️ 重要提醒
1. 程序**不会自动云端备份**，重要笔记请自行备份
2. 历史正文不允许修改，只能新增追加记录；仅标题、标签这类元信息可以调整
3. index.json 只是加速缓存，txt本体才是真实数据源
4. 布局尺寸常量统一放在代码头部，修改数值即可调整UI间隙、控件大小
